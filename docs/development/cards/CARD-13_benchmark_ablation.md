# CARD-13: 基准评测扩展与消融实验

| 属性 | 值 |
|---|---|
| 阶段 / 优先级 | 阶段4 / P1 |
| 对应选题 | 选题7 支撑（评分稳定性证据）+ 全部选题的答辩弹药 |
| 依赖 | CARD-04~09（被评测对象） |
| 状态 | ☐ 未开始 |

## 1. 目标

扩展现有 benchmark / ablation 体系：为阶段1/3 的全部新能力补评测任务，构建"有无辩论"等消融对比，产出答辩用的量化证据表。**评测是本项目的核心叙事**——评委要看的"结果稳定性、可复现"全靠这套。

## 2. 现状盘点

- `src/cn/benchmark.py`：离线基准（cn_agent_v1 任务集）。
- `src/cn/real_benchmark.py`：真实模型评测（需凭证，integration）。
- `src/cn/ablation_agent.py`：已有消融框架。
- 纪律：AGENTS.md 明令"dry-run/mock 评测结果不得作为真实模型性能"。

## 3. 详细设计

### 3.1 新增评测任务（注册进现有 benchmark 任务集，先读现有任务定义格式）

| 任务类别 | 用例来源 | 判定方式 |
|---|---|---|
| 趋势计算 | CARD-04 的封闭算例 | 数值精确匹配 |
| 背离/异常识别 | 构造含背离的合成快照 | 识别命中 + 零误报 |
| DCF/敏感性 | CARD-05 封闭算例 | 数值精确匹配 + 单调性 |
| 报告纠错 | CARD-06 六份评测集 | 命中率/误报率 |
| 质量评分 | 好/中/差三档报告 | 单调性 |
| 多智能体编排 | offline 轨迹 | 状态机完整性 + unsupported 标记正确性 |

### 3.2 消融实验矩阵（`src/cn/ablation_agent.py` 扩展）

| 消融维度 | 对比组 | 度量 |
|---|---|---|
| 辩论 vs 无辩论 | 单分析师直接出备忘录 vs 全流程 | 结论证据覆盖率、unsupported 率 |
| 温度稳定性 | 同输入多温度重跑（真实模型） | 结论方差（CARD-07 维度5 同源） |
| 工具数量 | 6 工具 vs 15 工具 | 任务完成率 |

真实模型消融结果与离线结果**物理隔离存储**：输出目录分开、报告文件名带 `real` 前缀、摘要页强制标注运行环境（模型/温度/日期）。

### 3.3 评测报告生成

~~~powershell
python -m src.cn.benchmark --suite cn_agent_v2 --out output/benchmark/
python -m src.cn.benchmark --suite cn_agent_v2 --ablation debate --out output/ablation/
~~~

输出 markdown 报告：任务通过率表、确定性模块误差表（应全零）、消融对比表。`cn_agent_v2` 为新增套件，`cn_agent_v1` 保持不动（向后兼容）。

## 4. 实施步骤

1. 通读 `benchmark.py` / `ablation_agent.py` / `real_benchmark.py` 的任务注册与报告结构。
2. 定义 `cn_agent_v2` 套件，迁移/新增 3.1 六类任务（全部离线）。
3. 扩展消融矩阵（辩论/工具数量离线可测；温度稳定性走 real 路径）。
4. 报告生成器扩展 + 环境 fingerprint（沿用现有 git commit/prompt hash 机制）。
5. 跑全套 → 结果贴执行备注（作为初赛材料素材）。

## 5. 验收标准

- [ ] `cn_agent_v1` 既有任务零回归；`v2` 新任务全离线可跑
- [ ] 消融三组对比可一键复现，报告含环境 fingerprint
- [ ] 真实/离线结果文件隔离 + 标注，测试断言混排时报错
- [ ] 全部测试通过

## 6. 红线（本卡特有）

- mock/dry-run 结果页面必须显著标注"非真实模型性能"
- 真实评测只在显式凭证与授权下运行（integration 标记）
- 评测代码不得为通过率特判任务（发现即回滚）
