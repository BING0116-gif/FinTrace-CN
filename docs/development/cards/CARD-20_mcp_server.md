## 1. 目标

把自有工具面暴露为标准 MCP 服务（stdio）。**入场合条件（三选一）**：工具确实需要独立服务部署；MCP 能实质改善解耦；能提高复现与扩展。仅为提交材料出现 "MCP" 字样 → **禁止实现**。

## 2. 约束（如实现）

- 官方 mcp SDK，**版本固定**并在依赖文件与第三方清单登记（许可证 MIT，提交前重新核实）
- 提供 **offline fallback**：MCP 不可用不阻塞任何主链功能
- **不得成为唯一运行路径**：全部能力保留原生工具入口
- 只做 server（暴露自有工具），不连接第三方 MCP 服务（守封闭环境）
- 白名单只读研究工具；调用产生与原生入口同构的轨迹记录

## 3. 其余字段

- **验收标准**：in-process 客户端测试（list_tools/往返/白名单外不暴露）离线通过；主链无 MCP 依赖断言
- **Demo Method**（决赛）：外部智能体经 MCP 调用本项目工具（可选展示，非核心）
- **决策记录**：无论最终做或不做，把决策与理由写入执行备注（答辩被问"MCP 呢"时有据可答）
