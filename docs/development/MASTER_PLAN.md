# FinTrace-CN v2 开发总指挥（Master Plan）

> 本文档是项目从"单体验证型 Demo"演进为"可参赛的投研智能体系统"的唯一进度真相源（single source of truth）。
> 所有模块开发以 `docs/development/cards/` 下的任务卡（CARD）为执行单元。执行任何卡片前，必须先阅读本文件第 7、8、9 节。

- 版本：v2.0
- 制定日期：2026-09-15
- 目标赛事：2026 年北京市大学生金融人工智能竞赛（初赛材料截止 10-18，决赛 11 月底）
- 上位规则：`AGENTS.md`（工作区级，永远优先于本文档）

---

## 1. 使命

构建一个**只面向 A 股**、可信、可验证、可复现的投研智能体系统。核心信任边界不变：

- Provider 事实、确定性计算、证据、模型叙事**四层永远分离**
- LLM 不做财务计算、不创建证据、不做校验决策
- 一切产出可追溯（Evidence ID）、可复现（离线测试）、可审计（运行轨迹）

## 3. v2 五层目标架构

```text
┌ 数据层     快照Provider(现有) | 公告年报解析(新) | AkShare扩展(新) | 快照Catalog(新) | 检索语料库(新)
│     ↓ 原始数据 → 结构化事实（挂 Evidence ID）
├ 领域计算层 同比环比背离(新) | DCF+敏感性(新) | 纠错核查(新) | 质量评分(新) | 相对估值(现有)
│     ↓ 全部确定性代码，输入输出可单测
├ 智能体编排层 分析师团队 | 多空辩论 | 报告生成CoT | Skill/Prompt资产(新) | 工具注册 6→15+ 【重点建设】
│     ↓ 原生状态机编排（不引入 LangGraph），借鉴 TradingAgents/FinRobot 模式（均 MIT）
├ 信任验证层 证据账本 | 财务校验 | 研究门禁 | 报告校验          【现有核心资产，只扩展不重写】
│     ↓ 每个新能力产出必须过 gate
└ 服务演示层 FastAPI(api.py) | Workbench组件化 | 统一任务队列(SQLite) | MCP Server(新) | 基准评测
```

关键决策：
1. 数据层与计算层全部确定性——LLM 永远不碰。
2. 编排逻辑原生实现（约 200 行状态机），不引入 LangGraph 重依赖。
3. 服务层统一任务系统，消掉现有 service/agent 双队列与 90KB 单文件 workbench。
4. **检索确定性优先**：BM25 自研实现（零向量库依赖），同查询必同结果；向量重排作为可选增强层，显式标注 model-dependent——"连检索都可复现"是差异化卖点。
5. **MCP 只做服务端**：把自有工具面暴露为标准 MCP 服务供外部智能体调用；不反向连接第三方 MCP 服务，守住封闭数据环境。

## 7. 卡片执行协议（Agent 使用说明）

1. **一次只执行一张卡**。开工前按顺序读：`AGENTS.md` → 本文件第 8/9 节 → 目标卡片全文。
2. 卡片是规格说明，不是死板脚本：执行中发现卡片与代码现状不符时，以现状为准做最小合理调整，并在卡内"执行备注"记录偏差。
3. 严格按卡内"实施步骤"推进；"验收标准"全项达成前不得声称完成。
4. 完成后：跑第 10 节验证命令 → 卡内状态打 `[x]` → 台账同步 → 提交 commit（遵循仓库既有提交风格）。
5. **禁止跨卡顺手改动**。发现别的问题，记录到卡片末尾"执行备注"，留给对应卡片。
6. 每张卡是一个可独立交付的增量：完成后系统必须处于全测试通过的可运行状态。

## 8. 统一工程契约

### 8.1 工具契约

新工具一律注册于 `src/agents/tools/cn_tools.py`，遵循现有工具模式（先读现有工具再动手）：

- 输入参数 JSON schema 明确、字段最小化
- 返回 `status: ok | error` 信封；error 时含 `error_code` 与人可读信息
- 所有事实型输出字段必须携带 `evidence_id` / `as_of` / 单位 / 期间
- 不在工具内调用 LLM（编排层除外，且必须留轨迹）

### 8.2 证据与快照

- 事实只来自快照 Provider；LLM 文本永不作为事实来源
- 市值与同业估值计算使用 RAW 价格（不做前复权）
- 新增数据字段：扩展 `src/cn/providers/`（akshare 优先），快照结构向后兼容
- 缺失/过期/混期间/混单位数据：拒绝或显式标注，不得静默填充

### 8.3 测试与离线纪律

- 默认测试离线、不依赖 `.env`、不依赖网络、不依赖墙钟时间
- 新模块配套 `tests/test_cn_<module>.py`；确定性模块的测试用手工可算的封闭数值
- golden/契约测试：`tests/` 下已有 35 个测试文件，新增不改坏存量
- 集成测试（需真实凭证）一律标 `@pytest.mark.integration`

## 9. 红线（违反即回滚）

1. 不引入 MongoDB / Redis / LangGraph / 前端框架
2. LLM 不做财务计算、证据创建、validator 决策
3. 不把 LLM 输出、演示样例数据呈现为 sourced financial facts
4. `data/`、`output/`、`.env`、付费数据、公告原文 PDF 不入 Git
5. 不复活已移除的美股/加密/预测市场/旧 supervisor 代码
6. mock/dry-run 评测结果不得冒充真实模型性能（决赛答辩会被追问）
7. 第三方开源依赖：新引入前查许可证并在第三方清单登记（MinerU 为 AGPL-3.0，只能作可选依赖并单独声明；mcp SDK 与 jieba 均 MIT）
8. MCP 只做服务端：仅暴露自有工具，不连接任何第三方 MCP 服务（守住封闭数据环境）
9. 检索结果永远带出处定位（文档/段落/证据 ID）；检索文本被引用时逐字引用并标注，不得被改写后冒充原文
